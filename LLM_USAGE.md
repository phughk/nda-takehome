# AI Tools used

## OpenCode + Qwen 3.5-35b-a3b over llama.cpp

After I had laid down the general design of what I wanted I fleshed out the implementation with OpenCode.

The initial guidelines were:
- main method structure
- service loop without explicit locks (writes and reads are coordinated as separate stages and batched)
- account lifecycle modelling supporting invariant checks
- most tests were auto-generated, but adapted to be better suited to what I am testing and validating (ex. testing vec equality instead of sizes, making sure intentional properties are being tested).

## Claude code (Sonet and Opus)

I used claude code with various models to confirm if details are missed.
The gitignore file describes some of the markdown files I generated to help with validation (identifying properties, edge cases, and testing for them).

The Qwen specification is also autogenerated as was the Dockerfile to create a helper instance to validate it.
I have reviewed the specs, and corrected the implementation based on findings from LLM misunderstandings.
An example of the misunderstandings were how locked accounts work and how it's possible to transition into chargeback state.

## DeepWiki

I used deepwiki a few times to confirm some understandings around libraries/frameworks (metrics vs opentelemtry for example).

## Context7

A neat little mcp for docs. It's plugged into OpenCode and Claude, so I haven't used it directly.
